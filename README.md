# 🎬 Кинопремьеры России — мониторинг 2026–2030

## Что готово
- Streamlit-дэшборд с поиском, фильтрами, графиками, выгрузкой Excel и CSV
- Исходная база из пользовательского Excel
- SQLite с историей изменений и журналом проверок
- Осторожный мониторинг календарей Кинопоиска 2026–2030
- GitHub Actions для ежедневного запуска (после публикации репозитория)

## Быстрый запуск
```bash
pip install -r requirements.txt
streamlit run app.py
```

## Ежедневный мониторинг
```bash
python monitor.py
```

Публикация: создать GitHub-репозиторий, загрузить **всё содержимое** этой папки, включить GitHub Actions и развернуть `app.py` в Streamlit Community Cloud. Запуск расписания GitHub Actions возможен с задержкой. Для приватной базы используйте приватный репозиторий и хостинг, поддерживающий приватные репозитории.

## Ограничения и честные статусы
- Исходные даты/рейтинги импортированы из прежнего файла, не проверены на сегодняшнюю дату.
- Мониторинг ищет фильмы в публичном HTML календарей, но сайт может отдавать JavaScript, CAPTCHA или HTTP 403; ошибки отражаются в журнале.
- Для новых фильмов календарный год **не** используется как точная дата релиза. Полнота и актуальность не гарантированы.
- Мониторинг не обещает обнаружение всех фильмов или всех переносов: без доступного структурированного источника дат это невозможно.
- История изменений начинается с момента импорта; ранее произошедшие переносы не реконструируются.
- Программа не обходит CAPTCHA и ограничения доступа.
- Поскольку GitHub Actions коммитит базу в репозиторий, публичный репозиторий делает её содержимое публичным.

## Следующий этап
Для гарантированного обновления дат подключите официальный лицензированный источник кинопроката/структурированный API, который отдаёт ID фильма и дату российского релиза. Добавьте парсер в `monitor.py` с `upsert(c, {...}, source)`.


## Обновление Кинопоиска (2026-11-23)
Сценарий `monitor.py` проверяет 60 помесячных страниц российского календаря 2026–2030, а также ограниченное количество карточек фильмов. Используются `div.premier_item`, `meta[itemprop=startDate]` и публичный `window.Ya.__ssr_initial_data`. Все проверки регистрируются в SQLite. Подтверждённые изменения дат сохраняются в журнале. Работа зависит от доступности Кинопоиска из GitHub Actions; CAPTCHA не обходится. Авторизационные cookie из исследовательского ноутбука не копируются в репозиторий.


## Единственный источник

Начиная с 26 ноября 2026 года проект использует **только Кинопоиск**.
Скрипт `monitor.py` собирает российские кинопремьеры 2026–2030,
карточки, рейтинги, число оценок и доступные отметки «Буду смотреть».
Ежедневный GitHub Actions выполняет `cleanup_secondary.py` перед сбором:
он удаляет записи прежнего второго источника и восстанавливает поля,
если последняя запись в журнале изменений была сделана им.
Исходные подтверждённые записи Кинопоиска и история их переносов сохраняются.

## Доступность сайта

Бесплатный Streamlit Community Cloud усыпляет приложение после 12 часов
без трафика; пробудить его может любой посетитель, не только владелец.
GitHub Actions выполняет проверки независимо от спящего интерфейса.
Если нужен сайт без экрана пробуждения, требуется хостинг с постоянно
работающим сервером (например, платный веб-сервис Render или Cloud Run
с минимум одной работающей инстанцией). Размещение на такой платформе
и платный тариф требуют отдельной авторизации владельца.
